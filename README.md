# 🏋️‍♂️ GymAnalysis - Платформа для Фітнесу та Аналітики

Цей проект є комплексною платформою для фітнесу, яка поєднує в собі управління тренуваннями, велику базу даних вправ (з підтримкою глобального пошуку та інтерактивної карти тіла), а також AI-блог, який автоматично генерує статті про спорт та здоров'я за допомогою Google Gemini.

Проект розділений на дві основні частини (Monorepo):
1.  **Frontend** (Клієнтська частина, побудована на React/Vite)
2.  **Backend** (Серверна частина, побудована на NestJS)

Код також підготовлено до розгортання в безсерверному середовищі (serverless), наприклад, на платформі **Vercel**.

---

## 🛠 Технологічний Стек (Tech Stack)

### 🎨 Frontend
*   **Фреймворк:** React 18 + Vite (швидка збірка та HMR)
*   **Маршрутизація:** React Router v6
*   **Стилізація:** Tailwind CSS (Vanilla CSS для гнучкості)
*   **Анімації:** Framer Motion (для плавних переходів та анімацій компонентів)
*   **Іконки:** Lucide React
*   **Спеціальні компоненти:** 
    *   `react-body-highlighter` (для інтерактивної SVG-карти м'язів)
*   **Управління станом:** React Hooks (`useState`, `useEffect`)

### ⚙️ Backend
*   **Фреймворк:** NestJS (сучасний, модульний Node.js фреймворк, що базується на TypeScript)
*   **База даних:** MongoDB (NoSQL)
*   **ORM / ODM:** Mongoose (схеми та моделі для MongoDB)
*   **Автентифікація та Безпека:** 
    *   Passport.js
    *   JWT (JSON Web Tokens)
    *   Захист маршрутів через кастомні Guards у NestJS
*   **Штучний Інтелект (AI):** `@google/generative-ai` (інтеграція з моделлю **Gemini 2.5 Flash** для генерації статей блогу)
*   **Кешування:** `@nestjs/cache-manager` (для зберігання AI-статей у пам'яті сервера, щоб зменшити кількість запитів до API Gemini; також є конфігурація для Redis)
*   **Інтеграції (API):** ExerciseDB (через RapidAPI) для отримання понад 1300+ вправ.

## 🏗 Основні Модулі та Функціонал

1.  **Інтерактивна Карта Тіла (Home):** Публічна головна сторінка, де користувачі можуть вибрати цільові м'язи на 3D/2D моделі тіла.
2.  **Бібліотека Вправ (`/exercises`):** Глобальний пошук із підтримкою пагінації (`limit`, `offset`), відображенням у вигляді сітки/таблиці та пошуком за назвою чи цільовим м'язом.
3.  **Конструктор Тренувань (`/workouts`):** Захищена зона для авторизованих користувачів, де можна створювати свої тренування, додавати вправи та редагувати підходи (sets), повторення (reps) та вагу.
4.  **AI Блог (`/blog`):** Сторінка з динамічним контентом, що автоматично генерується штучним інтелектом (Gemini) у суворому форматі JSON та кешується на бекенді.
5.  **Панель Керування / Хаб (`/dashboard`):** Персональна сторінка спортсмена з доступом до інструментів та профілю.

## 🚀 Налаштування та Запуск

### Попередні вимоги:
*   Встановлений **Node.js** (бажано версії 18+ або 20+)
*   Встановлений **npm** або **yarn**
*   Локальна або хмарна база даних **MongoDB** (наприклад, MongoDB Atlas)

### 1. Налаштування Backend (Сервера)
1. Відкрийте термінал та перейдіть до папки сервера: `cd backend`
2. Встановіть залежності: `npm install`
3. Створіть файл `.env` у корені папки `backend` і вкажіть необхідні змінні:
   ```env
   # Рядок підключення до бази даних
   MONGODB_URI=mongodb+srv://<ваш_логін>:<ваш_пароль>@<ваш_кластер>.mongodb.net/...
   
   # Секретний ключ для шифрування токенів авторизації
   JWT_SECRET=super_secret_jwt_key
   
   # API ключ для генерації блогів через Google Gemini
   GEMINI_API_KEY=AIza...
   
   # (Опціонально) API ключ для бази вправ ExerciseDB через RapidAPI
   RAPIDAPI_KEY=ваш_ключ
   ```
4. Запустіть сервер: `npm run start:dev` (Сервер буде доступний за адресою `http://localhost:3000`)

### 2. Налаштування Frontend (Клієнта)
1. Відкрийте новий термінал та перейдіть до папки клієнта: `cd frontend`
2. Встановіть залежності: `npm install`
3. (Опціонально) Якщо потрібно, налаштуйте `.env` файл для фронтенду, якщо бекенд розгорнуто не на localhost. (Зараз у коді налаштовано автоматичне визначення локального хоста).
4. Запустіть клієнт: `npm run dev`
5. Відкрийте браузер за адресою: `http://localhost:5173`

## 🔒 Додаткові Зауваження з Безпеки
*   Бекенд використовує DTO (Data Transfer Objects) та схеми валідації (`ValidationPipe`), щоб захистити API від некоректних даних.
*   Змінювати деталі тренування (підходи, вагу) може **тільки його автор**. Для цього на бекенді (у контролері тренувань) перевіряється JWT-токен та ID користувача.
*   Зовнішні ключі (Gemini, Mongo) ніколи не повинні потрапляти у публічні репозиторії! Завжди використовуйте файл `.env`.
